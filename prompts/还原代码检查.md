# 任务
我在做面试手写题训练，同目录下有两个文件：
- 标准写法（原版，不要修改）：`{原版文件路径，例如 javascript/promise/promise.js}`
- 我手写还原的版本（待检查）：`{copy 文件路径，例如 javascript/promise/promise.copy.js}`

请对照原版检查我的实现，不要直接修改我的文件，只输出检查报告。

# 检查要求
1. **以语义/行为一致为准，不要求逐字符相同**。变量命名、代码排版、注释差异不算错误，但核心逻辑、API 签名、边界处理必须一致。
2. 逐项对比：
   - 功能点是否完整（原版有哪些函数/方法/分支，我是否都实现了）
   - 核心逻辑是否正确（状态流转、回调时机、this 指向、返回值等）
   - 边界情况是否遗漏（异常捕获、参数校验、值穿透、空输入等）
   - 是否有原版没有但我多加的、或会导致行为差异的代码
3. 按严重程度分级报告：
   - 🔴 严重：会导致运行结果错误或功能缺失
   - 🟡 注意：边界情况/行为细节与原版不一致
   - 🟢 提示：风格或写法差异，不影响正确性
4. 每个问题给出：
   - 我代码中的位置（引用具体代码片段）
   - 原版对应写法（引用具体代码片段）
   - 为什么这是问题 / 会导致什么结果
   - 修改建议（只说思路或给出关键代码，不要直接改我的文件）
5. 最后给出：
   - 还原度评分（0-100）
   - 一句话总结：最需要优先修复的 1-3 个问题
   - 如果完全一致，明确告诉我「已通过」，不要为了凑内容硬挑毛病

# 输出格式
用中文输出，结构清晰，先给结论（通过/不通过），再列问题清单。

# 可选：实际运行验证
如有必要，可以编写临时测试用例实际运行验证行为差异，但不要改动两个源文件。

## 使用说明
使用时把开头的两个占位路径替换为实际文件路径：
- 原版：`javascript/xxx/xxx.js`
- 手写：`javascript/xxx/xxx.copy.js`
